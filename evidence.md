## Top 8 checks for QA (frequency x severity)

1. **Prod deploy parity (rows 1, 2, 3).** Highest severity: two prod outages. If the diff touches `migrations/` or dependency/build manifests, confirm the migration is applied to prod (host verified) and a Vercel preview route returns 200.
2. **Async stale/optimistic guard audit (rows 10, 14, 16).** Highest frequency, 4 or more hits. Every mutation must bump the request counter, restore state on failure, and re-issue any refresh it cancels.
3. **Idempotency/duplicate-write trace (rows 11, 12, 13).** Follow the client id from POST through retry, edit, Retake and reopen. Test "server committed, response lost" and overlapping calls.
4. **API input-boundary fuzz (rows 4, 5, 6, 7, 8).** Run schemathesis plus explicit boundary posts: explicit null on PATCH, NULL idempotency compare, derived decimals vs numeric scale, NUL/`%`/`_`, near-cap payload vs the Vercel limit.
5. **Spec literal diff (rows 19, 20).** Extract every quoted string, number and CHECK limit from the spec and `grep -F` each in the diff. Compare client `maxLength` to the DB constraint.
6. **Shared-function regression (rows 15, 21, 22, 24).** List the callers of every changed shared handler. Run the other flows' e2e. Test cancel/back with typed input and a late response.
7. **Run it, don't read it (rows 9, 27, 28, 33, 34).** `tsc`, `eslint --max-warnings 0`, pytest, drift check and e2e at 390 and 320 px against the web preview. Require a RED run and forced-failure cases. Report anything not run as "not verified".
8. **UI structure/a11y static scan (rows 25, 26, 17, 18).** No nested interactives, no hex literals outside tokens, 3:1 contrast on controls, separate load vs action error state, permission re-check on resume.
